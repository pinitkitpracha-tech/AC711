# AC711 — สเปกรวมของระบบ (สำหรับโคลนเป็นแบรนด์ใหม่)

เอกสารนี้รวม "ชุดคำสั่ง" ทั้งหมดที่ใช้สร้างระบบนี้ไว้ในที่เดียว ใช้ได้ 2 ทาง

1. **โคลนแบบเหมือนเดิมเปลี่ยนแค่ชื่อ (แนะนำ, 10 นาที)** — ไม่ต้องเขียนใหม่ ใช้ `scripts/rebrand.js` กับโค้ดชุดนี้ ดูหัวข้อ A
2. **สั่งสร้างใหม่จากศูนย์** — ส่งหัวข้อ B ทั้งหมดให้ผู้ช่วย AI พร้อมไฟล์ต้นฉบับ (ผลลัพธ์จะ "ใกล้เคียง" ไม่ใช่เหมือนทุกบรรทัด เพราะโค้ดถูกเขียนและแก้บั๊กสะสมมาหลายรอบ)

---

## A. วิธีโคลนระบบเดิมเปลี่ยนชื่อ (ผลลัพธ์เหมือนเดิม 100%)

```bash
# 1) สร้าง repo ใหม่บน GitHub (ว่างเปล่า) แล้วโคลนโค้ดชุดนี้
git clone https://github.com/pinitkitpracha-tech/ac711 newbrand
cd newbrand && rm -rf .git && git init -b main

# 2) เปลี่ยนชื่อแบรนด์ โดเมน อีเมล และตัวย่อบนโลโก้ (ทุกไฟล์ที่เกี่ยวข้อง)
node scripts/rebrand.js --name "NEWBRAND" --domain www.newbrand.com --email sales@newbrand.com --mark "NB"

# 3) ตรวจว่า build และทดสอบผ่าน
npm install && npm test

# 4) push ขึ้น repo ใหม่ แล้ว deploy ด้วย Render Blueprint ตาม README.md
git add -A && git commit -m "New brand" && git remote add origin https://github.com/<owner>/<repo>.git && git push -u origin main
```

สิ่งที่ `rebrand.js` เปลี่ยนให้: ชื่อที่แสดงทุกจุด (หน้าเว็บ ระบบ อีเมล ใบกำกับภาษี ประกาศ PDPA คู่มือ), โดเมน, อีเมลฝ่ายขาย/ผู้ส่ง, ตัวย่อบนโลโก้, ชื่อร้านสาธิต · สิ่งที่**ไม่**เปลี่ยน (เป็นชื่อภายในของโค้ด ไม่มีผลกับผู้ใช้): เส้นทาง API `/api/ac711`, คีย์ใน localStorage, ชื่อไฟล์ `ac711.html`, ชื่อแพ็กเกจ

หลัง deploy ให้ตั้งค่าใน Admin Console → เนื้อหาเว็บไซต์ (ชื่อนิติบุคคล ที่อยู่ เลขผู้เสียภาษี DPO บัญชีรับโอน) และแก้ธีมสีถ้าต้องการ (ตัวแปร `--amber` ใน CSS ของ `ac711.html`)

## B. สเปกรวม (ชุดคำสั่งที่ใช้สร้างระบบ เรียงตามลำดับที่สั่ง)

### B1. ระบบบริหารร้านอะไหล่และสาขา (ไฟล์เดียว `ac711.html`)
- ตั้งชื่อระบบ "<แบรนด์> ระบบบริหารร้านอะไหล่และสาขา" โทนสีส้ม-เทาอ่อน
- สาขาใช้รหัส 0000 (สำนักงานใหญ่), 0001, 0002 … แทนชื่อจังหวัด ห้ามมีชื่อร้านต้นแบบเดิมเหลืออยู่ทั้งไทย/อังกฤษ
- โมดูล: แดชบอร์ด, POS, ออเดอร์ออนไลน์, แชท, ลูกค้า, สินค้า, สต็อกหลายสาขา, จัดซื้อ (PO/GR/ผู้จำหน่าย/ค่าใช้จ่าย), โอนย้าย, อนุมัติ, พยากรณ์, รายงาน, บัญชี (ลูกหนี้ เจ้าหนี้ สมุดรายวัน งบ ภาษี ปิดงวด), บุคคล (พนักงาน สิทธิ์ ลา เวลา เงินเดือน ประเมิน), AI ผู้ช่วย, การตลาด, เรียนรู้, ตั้งค่า, ตั้งค่าสาขา, รายรับ
- ทุกหน้ารองรับ desktop / tablet / mobile หน่วย rem/em

### B2. POS และการชำระเงิน
- ชำระเงินพิมพ์ตัวเลขจากแป้นพิมพ์ได้โดยไม่ต้องมีเครื่อง POS; รองรับเครื่องยิงบาร์โค้ดแบบคีย์บอร์ดและกล้องมือถือ
- **ชำระบางส่วน**ได้ทั้งบิลขายและบิลซื้อ แสดงยอดคงค้าง กลับมารับชำระจนครบ ทุกงวดออกใบเสร็จได้ แสดงสถานะคงค้าง
- ทุกเอกสารซื้อ-ขายมีปุ่มสถานะ ชำระแล้ว / ค้างบางส่วน / รับชำระเงิน (กดแล้วไปหน้ารับ-จ่ายชำระของคู่ค้ารายนั้น)
- คลิกเอกสารในลูกหนี้/เจ้าหนี้ต้องเปิดรายละเอียดได้
- ตะกร้า POS: ช่องว่างหลังรายการเป็นปุ่มลบ; แต่ละรายการแสดง 2 บรรทัด (รหัส / ชื่อ) ชื่อแก้ได้เฉพาะบิลนั้น ไม่กระทบทะเบียน
- ใบเสร็จอย่างย่อ (58/80 มม.) และใบกำกับภาษีเต็มรูป A4 พร้อมจำนวนเงินเป็นตัวอักษร

### B3. สินค้า หมวด สาขา
- หมวดสินค้าเพิ่มรูปได้ (กรอบ + สำหรับอัปโหลด)
- ปุ่ม "เพิ่มสินค้าใหม่" เห็นชัดเจน ฟอร์มครบ (SKU ชื่อ หมวด ยี่ห้อ หน่วย ต้นทุน ราคาปลีก/ส่ง/ออนไลน์ บาร์โค้ด รับประกัน รูป)
- ตั้งค่าองค์กรกำหนดจำนวนสาขาและตั้งชื่อได้ มีเมนูตั้งค่าสาขาแยก

### B4. เว็บไซต์ + สมัครทดลองใช้ + Admin Console
- หน้าแรก www.<โดเมน> มีปุ่ม เข้าสู่ระบบ / สมัครใช้บริการ; หน้าเข้าสู่ระบบพื้นส้ม มีเฉพาะ ชื่อผู้ใช้ รหัสผ่าน ลืมรหัสผ่าน
- สมัครทดลองใช้ฟรี 30 วัน กรอกข้อมูลผู้สมัครมาตรฐาน มี popup PDPA ตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล 2562 ต้องกดยอมรับ; ระบบสร้างรหัสผ่าน ส่งอีเมล ผู้สมัครกดยืนยันแล้วใช้ได้ทันที
- ค่าบริการรายปี 18,000 บาท ไม่รวม VAT
- Admin Console (หลังบ้านผู้ให้บริการ): แก้เนื้อหาเว็บไซต์ทุกจุด, จัดการผู้ใช้บริการ, ล็อกเมื่อครบ 30 วันแต่ข้อมูลไม่หาย, ลูกค้าแจ้งชำระเงิน → แอดมินอนุมัติเพื่อใช้ต่อ (+1 ปี), บันทึกการใช้งานทั้งหมดเพื่อวิเคราะห์
- ตั้งค่าร้าน: ที่อยู่, เลขผู้เสียภาษี 13 ช่อง, สิทธิ์พนักงานถึงเมนูย่อยของทุกเมนู (ต่อบทบาทและรายบุคคล), จำนวนสาขา

### B5. ข้อมูล การนำเข้า-ส่งออก และประวัติ
- ตั้งค่าร้านมีการ์ด "ลบข้อมูลทดสอบระบบ" (เฉพาะรายการเคลื่อนไหว / ทั้งหมด) และ "ส่งออกข้อมูลทั้งหมด" (JSON) + "กู้คืนจากไฟล์สำรอง"
- ทุกเมนูมีการ์ดนำเข้า (CSV พร้อมไฟล์ตัวอย่าง) และส่งออก (CSV รายตาราง); นำเข้ายอดยกมา สต็อก/ลูกหนี้/เจ้าหนี้
- เจ้าของร้านดูประวัติการแก้ไขของพนักงานทุกคนได้ (กรองรายคน)
- เมนู "รายรับ": ยอดขายรายวันรายบิล เรียงตามเวลา ค้นหาได้ เลือกช่วง วันนี้/เดือนนี้/ปีนี้/ปีที่แล้ว (พ.ศ.)
- กราฟ: ตัวอักษรแกนไม่ทับกัน ลดขนาด/เว้นป้ายอัตโนมัติ

### B6. เซิร์ฟเวอร์จริง (โฟลเดอร์นี้)
- Node 22 + Express + SQLite ในตัว; หลายร้านในเซิร์ฟเวอร์เดียว; รหัสผ่าน bcrypt; JWT; จำกัดอัตราการเดารหัส
- สมัคร/ยืนยันอีเมล/ลืมรหัส ผ่าน SMTP จริง (ไม่ตั้ง = แสดงอีเมลบนหน้าจอ)
- ล็อกเมื่อหมดอายุ (API 402) → แจ้งชำระเงิน+สลิป (+หัก ณ ที่จ่าย 3%) → แอดมินอนุมัติ → ใบกำกับภาษี INV-YYYYMM-NNNN → อีเมลแจ้ง
- cron: เตือนหมดอายุ 7 วัน/1 วัน, ลบผู้สมัครไม่ยืนยันใน 30 วัน, รีเซ็ตร้านสาธิตรายวัน
- AI ใช้ Claude จริงเมื่อมี `ANTHROPIC_API_KEY`
- ร้านสาธิต owner/ac1234 ใช้ร่วมกัน ห้ามลบ/แก้ตั้งค่า
- ความปลอดภัย: อัปโหลดเฉพาะรูป, สิทธิ์จัดการพนักงานเฉพาะเจ้าของ/ผู้จัดการ, PIN ≥ 4 หลัก, แยกข้อมูลระหว่างร้าน, admin ค่าเริ่มต้นใช้ใน production ไม่ได้
- ชุดทดสอบ `npm test` 62 ข้อ; deploy ด้วย `render.yaml` (Render) หรือ `Dockerfile`

### B7. ข้อจำกัดที่รับทราบ
- LINE / Facebook / Shopee / Lazada / TikTok เป็นการจำลอง ยังไม่เชื่อม API จริง
- เครื่องพิมพ์ใบเสร็จผ่านการพิมพ์ของเบราว์เซอร์ ไม่เชื่อมลิ้นชักเงินสด
- ข้อมูลร้านหนึ่งเก็บเป็น JSON ก้อนเดียวใน SQLite เหมาะกับร้านขนาดกลาง
