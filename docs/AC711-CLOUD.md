## 2. ลำดับการใช้งานที่ออกแบบไว้ (ทำงานได้ในไฟล์สาธิต)

1. เปิด www.ac711.com → หน้าแรก (ฟีเจอร์ ราคา ปุ่ม "เข้าสู่ระบบ" และ "ทดลองใช้ฟรี 30 วัน")
2. กด "เข้าสู่ระบบ" → หน้าพื้นสีส้ม มีเพียง ชื่อผู้ใช้/อีเมล รหัสผ่าน และลิงก์ "ลืมรหัสผ่าน"
3. กด "ทดลองใช้ฟรี 30 วัน" → ฟอร์มสมัคร: ชื่อร้าน ประเภทธุรกิจ ชื่อ-นามสกุล ตำแหน่ง อีเมล เบอร์โทร จังหวัด จำนวนสาขา เลขผู้เสียภาษี (ไม่บังคับ) ช่องทางที่รู้จัก
4. กด "ถัดไป" → ป๊อปอัปประกาศความเป็นส่วนตัว (PDPA) + ข้อกำหนดการใช้บริการ ต้องติ๊กช่อง "รับทราบ/ยอมรับ" ก่อน ปุ่มยอมรับจึงกดได้ ช่องรับข่าวสารเป็นทางเลือก
5. ระบบสร้างบัญชี (สถานะรอยืนยัน) และส่งอีเมล: ชื่อผู้ใช้ = อีเมล, รหัสผ่านชั่วคราว 8 ตัว, ปุ่มยืนยัน
6. ผู้สมัครกดยืนยันในอีเมล → บัญชีเปิดใช้ ระยะทดลอง 30 วันเริ่มนับ → กลับหน้าเข้าสู่ระบบพร้อมกรอกอีเมลให้
7. เข้าสู่ระบบ → ใช้งานได้ทันที แถบบนแสดง "ทดลองใช้ · เหลือ N วัน · สมัครรายปี" กดแล้วเห็นราคาและช่องทางชำระเงิน
8. ครบ 30 วัน → เข้าสู่ระบบไม่ได้ ระบบแสดงแพ็กเกจรายปีให้สมัคร (ข้อมูลเก็บไว้ 60 วันตามข้อกำหนด)
9. ลืมรหัสผ่าน → กรอกอีเมล → อีเมลลิงก์ตั้งรหัสใหม่ (อายุ 60 นาที) → ตั้งรหัสใหม่ → เข้าสู่ระบบ

ในไฟล์สาธิต อีเมลถูกจำลองเป็น "กล่องจดหมายจำลอง" บนหน้าจอ และบัญชีเก็บใน `localStorage` ของเบราว์เซอร์ (`ac711_accounts`) แล้วนำกลับเข้าฐานข้อมูลจำลองทุกครั้งที่โหลดหน้า

## 2.1 การชำระเงินหน้าร้านและเอกสารซื้อ-ขาย

- หน้าชำระเงิน POS พิมพ์จำนวนเงินจากแป้นพิมพ์จริงได้ (ตัวเลข จุดทศนิยม Backspace และ Enter เพื่อยืนยัน) ควบคู่กับแป้นตัวเลขบนจอ ไม่ต้องต่ออุปกรณ์ POS
- ติ๊ก "รับชำระบางส่วน" ได้ทุกวิธีชำระ (ยกเว้นเครดิตซึ่งเป็นลูกหนี้ทั้งยอด) ระบบบันทึกยอดที่รับจริง ยอดที่เหลือตั้งเป็นลูกหนี้ค้างชำระ (สมุดรายวันขาย: เดบิตเงินสด/ธนาคารตามที่รับ + เดบิตลูกหนี้ 1130 ส่วนที่ค้าง) ถ้าไม่ได้เลือกลูกค้าในระบบต้องกรอกชื่อและเบอร์โทรเพื่อติดตาม
- บิลขายทุกใบแสดงสถานะ "ชำระแล้ว / คงค้างบางส่วน" และบิลที่ค้างมีปุ่ม "รับชำระเงิน" ในประวัติบิลและในใบเสร็จ กดแล้วไปหน้าลูกหนี้รายนี้ (บัญชี & การเงิน → ลูกหนี้) พร้อมเปิดฟอร์มรับชำระให้ทันที รับบางส่วนได้จนครบ เมื่อครบยอดบิลจะเปลี่ยนเป็น "ชำระแล้ว" อัตโนมัติ ผู้ใช้ที่ไม่มีสิทธิ์เข้าบัญชี (แคชเชียร์) รับชำระด่วนได้จากหน้า POS
- หน้าลูกหนี้/เจ้าหนี้: คลิกใบแจ้งหนี้ใดก็ได้เพื่อเปิดรายละเอียด แสดงยอดบิล รับ/จ่ายแล้ว คงค้าง สถานะ และประวัติการชำระทีละงวดพร้อมยอดคงค้างหลังแต่ละงวด พิมพ์ใบเสร็จรับเงิน/ใบสำคัญจ่ายของงวดนั้นได้ และกด "รับชำระ / จ่ายชำระ" เพื่อชำระเพิ่มแบบบางส่วนได้จนครบ
- ทุกการรับ/จ่ายชำระ ระบบยืนยันยอดคงค้างที่เหลือทันที (ข้อความแจ้งเตือน + บรรทัด "คงค้างหลังชำระ" บนใบเสร็จและใบสำคัญจ่าย)
- ตะกร้า POS แสดง 2 บรรทัด (รหัสสินค้า / ชื่อสินค้า) แก้ชื่อสินค้าได้เฉพาะบิลนั้น ไม่กระทบทะเบียนสินค้า และมีปุ่ม "ลบ" ต่อรายการ
- บิลซื้อ (ใบรับสินค้า GR) แสดงคอลัมน์ "การชำระ": ค้างชำระ / คงค้างบางส่วน / ชำระแล้ว และปุ่ม "จ่ายชำระ" ที่พาไปหน้าเจ้าหนี้รายนี้พร้อมเลือกผู้จำหน่ายให้ จ่ายบางส่วนได้เช่นกัน (ผ่านใบสำคัญจ่ายที่ต้องอนุมัติตามวงเงิน)

## 2.2 สินค้า หมวดสินค้า และโครงสร้างสาขา

- ปุ่ม "➕ เพิ่มสินค้าใหม่" อยู่ที่หัวหน้าสินค้า (ทุกบทบาท) และบนแถบเครื่องมือหน้า POS ฟอร์มมีรูปสินค้า 4 รูป บาร์โค้ด หมวด ยี่ห้อ รุ่น สเปก ราคาทุน/ปลีก/ส่ง/ออนไลน์ ประกัน วันหมดอายุ รุ่นรถที่ใส่ได้ และ Min/Max ต่อสาขา
- หมวดสินค้า (ตั้งค่า → หมวดสินค้า) เพิ่มรูปได้จากกรอบ ＋ ทั้งตอนสร้างหมวดใหม่และหมวดที่มีอยู่ รูปแสดงบนแถบหมวดในหน้า POS
- ตั้งค่า → สาขา: กำหนด "จำนวนสาขาที่ใช้งาน" แล้วกดปรับ ระบบสร้างรหัส 0001, 0002, … ให้อัตโนมัติ (ลดจำนวน = ปิดใช้งานสาขาท้ายสุด ข้อมูลยังอยู่) ตั้งชื่อแต่ละสาขาได้ในตารางทันที และยังเพิ่มสาขาแบบกำหนดเองได้

## 2.3 Admin Console (หลังบ้านผู้ให้บริการ) — เปิดที่ `#/admin` (ลิงก์ "ผู้ดูแลระบบ" ท้ายหน้าเว็บ) ค่าเริ่มต้น admin / admin711

- **แดชบอร์ด** จำนวนผู้สมัคร ทดลองใช้ รายปี หมดอายุ/ระงับ แจ้งชำระเงินรอตรวจ รายได้ที่อนุมัติ ผู้ใช้ที่ใช้งานใน 7 วัน บัญชีใกล้หมดอายุ
- **ผู้ใช้บริการ** รายชื่อร้านที่สมัคร กรองตามสถานะ คลิกเพื่อดูข้อมูลผู้สมัคร ความยินยอม PDPA การใช้งาน ประวัติชำระเงิน และสั่งงาน: รีเซ็ตรหัสผ่าน ขยายทดลอง 7 วัน ระงับ/ปลดระงับ อนุมัติรายปี (+1 ปี)
- **แจ้งชำระเงิน** ผู้ใช้ที่หมดอายุกด "แจ้งชำระเงิน" แนบสลิป → แอดมินเห็นการ์ดรอตรวจ กด "อนุมัติ" ระบบเปิดใช้งานรายปีให้ทันที (นับ +1 ปีจากวันหมดอายุเดิม) หรือปฏิเสธพร้อมเหตุผล
- **บันทึกการใช้งาน** ทุกหน้าที่เปิด ทุกการกระทำ (สร้าง/แก้ไข/ลบ) การเข้า-ออกระบบ การสมัคร การแจ้งชำระ และการกระทำของแอดมิน แยกตามร้าน/ผู้ใช้/สาขา/อุปกรณ์ กรองตามร้าน ประเภท ช่วงเวลา และดาวน์โหลด CSV เพื่อวิเคราะห์และพัฒนาระบบ
- **เนื้อหาเว็บไซต์** แก้ข้อความทุกส่วนของหน้าเว็บ (แบรนด์ ปุ่ม Hero ฟีเจอร์ 6 ข้อ ราคา VAT วันทดลองใช้ สิ่งที่ได้รับ ขั้นตอน ข้อมูลบัญชีรับโอน ท้ายเว็บ) และข้อมูลผู้ควบคุมข้อมูลในประกาศ PDPA บันทึกแล้วมีผลทันที
- **ตั้งค่าแอดมิน** เปลี่ยนรหัสผ่านผู้ดูแล ล้างบันทึกการใช้งาน ส่งออกข้อมูลผู้สมัคร

วงจรบัญชีผู้ใช้: สมัคร → ยืนยันอีเมล (รับรหัสผ่านที่ระบบสร้าง) → ทดลองใช้ 30 วัน → หมดอายุ: ระบบล็อกการเข้าใช้ ข้อมูลยังอยู่ → แจ้งชำระเงิน → แอดมินอนุมัติ → ใช้งานรายปี → หมดอายุรายปีล็อกอีกครั้งจนกว่าจะชำระรอบใหม่

## 2.4 การตั้งค่าร้าน สาขา และสิทธิ์พนักงาน

- ตั้งค่า → ร้าน: ชื่อร้าน ที่อยู่ร้าน/ที่อยู่จดทะเบียน (พิมพ์บนใบกำกับภาษี) เลขประจำตัวผู้เสียภาษีแบบ 13 ช่อง (พิมพ์ต่อเนื่อง/วางได้ ต้องครบ 13 หลัก) และ "จำนวนสาขาที่ใช้งาน" ของร้าน
- เมนู "ตั้งค่าสาขา" (และแท็บสาขาในตั้งค่า): ชื่อ ที่อยู่ เบอร์โทร สี สถานะเปิด/ปิด ของแต่ละสาขา
- สิทธิ์การใช้งานกำหนดได้ 2 ระดับ: ตามบทบาท (บุคคล → สิทธิ์การใช้ระบบ) และเฉพาะบุคคล (ตั้งค่า → พนักงาน → ปุ่ม "สิทธิ์") ทั้งสองระดับเลือกได้ถึงเมนูย่อยของทุกเมนู (จัดซื้อ เอกสาร&อนุมัติ รายงาน บัญชี บุคคล การตลาด ตั้งค่า) มีผลเมื่อล็อกอินใหม่

## 2.5 รายรับ ประวัติการแก้ไข นำเข้า-ส่งออก และการแสดงผล

- เมนู "รายรับ" (หลังร้าน): ยอดขายรายบิลเรียงตามเวลา จัดกลุ่มรายวันพร้อมยอดรวม เลือกช่วง วันนี้/สัปดาห์นี้/เดือนนี้/เดือนที่แล้ว/ปีนี้/ปีที่แล้ว/กำหนดเอง (แสดง พ.ศ.) ค้นหาเลขที่บิล ลูกค้า เบอร์โทร กรองวิธีชำระและสถานะ กดบิลเพื่อดูใบเสร็จ
- เมนูผู้ใช้ (มุมขวาบน) ของเจ้าของกิจการ/ผู้จัดการส่วนกลาง: "ประวัติการแก้ไขของพนักงานทั้งหมด" กรองตามพนักงาน ช่วงเวลา ค้นหา และดาวน์โหลด CSV (บันทึกแบบโซ่แฮช)
- ทุกเมนูมีการ์ด "นำเข้าข้อมูล" และ "ส่งออกข้อมูล" ท้ายหน้า: ส่งออก CSV รายตาราง (ผู้ใช้ระดับสาขาเห็นเฉพาะข้อมูลสาขาตน ตารางบัญชี/บุคคล/ตั้งค่าเฉพาะส่วนกลาง) นำเข้า CSV พร้อมไฟล์ตัวอย่างและตัวอย่างข้อมูลก่อนยืนยันสำหรับ สินค้า ลูกค้า ผู้จำหน่าย พนักงาน จุดสั่งซื้อ Min/Max และสาขา
- ตั้งค่า → ร้าน (เจ้าของกิจการ): การ์ด "ลบข้อมูลทดสอบระบบ" (เลือกลบเฉพาะรายการเคลื่อนไหว หรือรวมสินค้า/ลูกค้า/ผู้จำหน่าย ต้องพิมพ์ "ลบ" ยืนยัน) และ "ส่งออกข้อมูลทั้งหมด" เป็น JSON ไฟล์เดียว (ไม่รวมรหัสผ่านและกุญแจเชื่อมต่อ) ในเวอร์ชันสาธิตการลบจะถูกจำไว้ในเบราว์เซอร์และใช้ซ้ำทุกครั้งที่โหลด
- การแสดงผลใช้หน่วย rem/em ทั้งระบบ (ฐาน 15px = 93.75%, จอเล็กกว่า 420px ลดเป็น 14px, จอกว้างกว่า 1800px เพิ่มเป็น 17px) จึงขยาย-ย่อตามอุปกรณ์และการตั้งค่าขนาดตัวอักษรของผู้ใช้ เส้นขอบ 1–2px คงเป็น px เพื่อความคมชัด

## 3. ข้อมูลที่ต้องเติมก่อนเปิดใช้จริง

ค่าต่อไปนี้แก้ได้จาก Admin Console → เนื้อหาเว็บไซต์ (บนเซิร์ฟเวอร์เก็บในฐานข้อมูล ค่าเริ่มต้นอยู่ที่ `src/site-defaults.json`) (ยังเป็นข้อความในวงเล็บเหลี่ยม ต้องแทนด้วยข้อมูลจริง) รวมถึงข้อมูลบัญชีรับโอนเงิน

- `controller` ชื่อนิติบุคคลผู้ให้บริการ (ผู้ควบคุมข้อมูลส่วนบุคคล)
- `address` ที่อยู่ผู้ให้บริการ
- `dpo_email` อีเมลเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล
- `sales_email` ปัจจุบันตั้งเป็น sale@ac711.com ตรวจสอบว่าใช้จริง
- `privacy_date` วันที่ประกาศมีผล

## 4. เซิร์ฟเวอร์จริง (โฟลเดอร์ `ac711/`) — สร้างแล้ว

ระบบสาธิตในไฟล์ `ac711.html` ถูกใช้เป็น "แหล่งเดียว" ของทั้งหน้าเว็บและ API ของร้าน: คำสั่ง `npm run build` ในโฟลเดอร์ `ac711/` จะแยกบล็อก backend จำลองออกมาเป็น `build/tenant-api.js` (รันบนเซิร์ฟเวอร์ 1 ชุดต่อร้าน) และสร้าง `public/index.html` (หน้าเว็บที่คุยกับ API จริง) จึงแก้ฟีเจอร์ที่ไฟล์เดียวแล้ว build ใหม่ได้ตลอด

**สิ่งที่ทำงานแล้ว**
- หลายร้านในเซิร์ฟเวอร์เดียว: ข้อมูลแต่ละร้านแยกกันในตาราง `tenant_data` (SQLite ที่ `DATA_DIR`) บันทึกอัตโนมัติหลังทุกการเขียนและทุก 30 วินาที ร้านสาธิต (owner / ac1234 รหัสร้าน DEMO) อยู่ในหน่วยความจำอย่างเดียว
- สมัครทดลองใช้ → อีเมลยืนยัน (ลิงก์ใช้ครั้งเดียว) → เริ่มนับ 30 วันเมื่อยืนยัน → ล็อกอินไม่ได้จนกว่าจะยืนยัน
- รหัสผ่านทุกบัญชี (เจ้าของร้าน พนักงาน แอดมิน) เก็บเป็น bcrypt, โทเคน JWT อายุ 7 วัน, จำกัดอัตราการเดารหัส (login/signup/forgot/admin)
- พนักงานเข้าระบบด้วยชื่อผู้ใช้ของร้าน ถ้าชื่อซ้ำหลายร้านระบบจะขอ "รหัสร้าน" (S1001, S1002 …)
- หมดทดลองใช้/หมดรายปี/ถูกระงับ → API ตอบ 402 พร้อมข้อมูลแพ็กเกจ ข้อมูลของร้านไม่ถูกลบ เจ้าของร้านยังแจ้งชำระเงินได้ด้วยโทเคนเฉพาะกิจ (billing token)
- แจ้งชำระเงิน (แนบสลิป, เลือกหัก ณ ที่จ่าย 3%) → แอดมินอนุมัติ → ต่ออายุ +1 ปีจากวันหมดอายุเดิม → ออกใบกำกับภาษี `INV-YYYYMM-NNNN` (HTML พิมพ์/บันทึก PDF) และส่งอีเมลแจ้ง
- Admin Console บนเซิร์ฟเวอร์: แดชบอร์ด ผู้ใช้บริการ (รีเซ็ตรหัส ขยายเวลา ระงับ/ปลด อนุมัติรายปี ลบบัญชี) แจ้งชำระเงิน บันทึกการใช้งาน (ทุกร้าน ทุกหน้า ทุกการกระทำ) เนื้อหาเว็บไซต์ ตั้งค่าแอดมิน
- อีเมลจริงผ่าน SMTP (`SMTP_*`) ถ้ายังไม่ตั้งค่า ระบบแสดงอีเมลบนหน้าจอแทน (โหมดทดสอบ)
- งานตามเวลา: เตือนหมดอายุล่วงหน้า 7 วัน/1 วัน, ลบผู้สมัครที่ไม่ยืนยันอีเมลใน 30 วัน
- ผู้ช่วย AI ใช้ Claude จริงเมื่อใส่ `ANTHROPIC_API_KEY` (ส่งเฉพาะตัวเลขสรุปของร้าน ไม่ส่งข้อมูลส่วนบุคคลของลูกค้า)
- ยอดยกมาตอนเริ่มใช้จริง (สต็อก ลูกหนี้ เจ้าหนี้) นำเข้าจาก CSV, สำรอง/กู้คืนข้อมูลทั้งร้านเป็น JSON, ใบกำกับภาษีเต็มรูป A4 ต่อบิล
- ชุดทดสอบอัตโนมัติ `npm test` (50 ข้อ ครอบคลุมสมัคร-ยืนยัน-ขาย-รีสตาร์ท-ล็อก-ชำระ-อนุมัติ-ใบกำกับ-กู้คืน)

วิธีติดตั้งและตัวแปรแวดล้อมอยู่ใน `README.md` คู่มือผู้ใช้อยู่ใน `docs/USER-GUIDE.md`

**ข้อจำกัดที่ควรรู้**
- ออเดอร์จาก Shopee / Lazada / TikTok / LINE เป็นการจำลอง (ยังไม่เรียก API ของแพลตฟอร์ม) ต้องทำ integration แยกเมื่อมี credential ของร้าน
- เครื่องพิมพ์ใบเสร็จความร้อน 58/80 มม. ใช้ผ่านการพิมพ์ของเบราว์เซอร์ (ตั้งขนาดกระดาษในไดรเวอร์เครื่องพิมพ์) ยังไม่มีการเชื่อมตรงกับลิ้นชักเงินสด
- ข้อมูลร้านหนึ่งเก็บเป็น JSON ก้อนเดียวใน SQLite เหมาะกับร้านขนาดกลาง (หลักหมื่นบิลต่อปี) ถ้าโตกว่านั้นควรย้ายเป็นตารางต่อร้านหรือ PostgreSQL

## 5. รายการตรวจ PDPA ที่ระบบรองรับแล้ว

- ประกาศความเป็นส่วนตัวระบุผู้ควบคุมข้อมูล ข้อมูลที่เก็บ วัตถุประสงค์และฐานทางกฎหมาย (มาตรา 19, 24) การเปิดเผย การโอนไปต่างประเทศ (มาตรา 28-29) ระยะเวลาเก็บ สิทธิเจ้าของข้อมูล (มาตรา 30-36) และการแจ้งเหตุละเมิด (มาตรา 37)
- ขอความยินยอมแยกจากข้อความอื่น ภาษาชัดเจน ช่องรับข่าวสารไม่ติ๊กไว้ล่วงหน้า และถอนได้
- บันทึกเวอร์ชันประกาศและเวลาที่ยอมรับไว้กับบัญชี (`consent`)
- แยกบทบาท: AC711 เป็นผู้ประมวลผลสำหรับข้อมูลลูกค้า/พนักงานที่ร้านบันทึกในระบบ (ต้องมี DPA ในข้อกำหนดฉบับเต็ม)

ควรให้ที่ปรึกษากฎหมายตรวจข้อความฉบับเต็มอีกครั้งก่อนเปิดใช้จริง
